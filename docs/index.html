⚡ Quick Start Guide

Get up and running with Jigar Tools in less than two minutes.

1

Provision Device

Enable **USB Debugging** on your Android device (Settings > Developer Options > USB Debugging) and connect it to a high-speed USB 3.0 port on your PC.

2

Download & Extract

Grab the latest release archive Jigar_Tools_2.0-Gold.zip and extract it to a local folder (e.g. D:\jigar-tools\).

3

Launch Installer

Double-click Jigar_Tools_Setup.bat. The utility will automatically run UAC elevation, configure path settings, verify ADB availability, and open the Main Dashboard menu.

4

Run Sync / Restore

Select Option 1 to back up your phone, or Option 2 to restore snapshots. The interactive WinForms window will open automatically to let you refine your selection.

🛣️ Smart Virtual Drive Routing

How Jigar Tools bypasses Windows MAX_PATH (260 character) limits.

Why is this needed?

Android is Unix-based and allows deeply nested directory paths. Windows Win32 APIs crash when a file path exceeds 260 characters. Smart Routing dynamically shrinks destination prefixes.

Key Enhancements in v2.0-Gold

  • Case-Insensitive Normalization: Replaced buggy .NET starts-with checks with native PowerShell case-insensitive comparisons, ensuring that paths matching settings are always caught.
  • try/finally Execution Guard: The unmounting logic is wrapped in a script-wide finally block, so even if the pipeline crashes, your drives are cleaned up.
  • Lock Retry Loops: If Explorer locks the drive, the script retries 5 times with a 200ms sleep, avoiding silent failures.

🛡️ 3-Stage Fallback Architecture

The fail-proof pipeline ensuring that 100% of Android files are successfully backed up.

1

Direct Pull

Standard ADB interface pull

2

Temp Copy

ADB Sandbox (/data/local/tmp)

3

Root Mount

Elevated su global namespace cp

Detailed Pipeline Breakdown

  1. Stage 1 (Direct Pull): Standard Toybox/Toolbox call. Fast and efficient. Covers 95% of user files.
  2. Stage 2 (Device Temp Copy): If direct pull fails due to strict file read/ownership locks, the file is duplicated to the ADB-accessible sandbox folder /data/local/tmp on the device, pulled, and deleted.
  3. Stage 3 (Root Global Mount): For rooted devices (APatch, Magisk, KernelSU), the script elevates execution to su to bypass security boundaries, copy file structures out of restricted system storage, and retrieve them safely.

📋 Troubleshooting & FAQ

Find fast solutions to common ADB, virtual drive, and sync issues.

Why is there a virtual "Z:" drive left in my Explorer?

If the script window is closed abruptly (e.g., clicking "X" instead of letting the script finish), the unmount command is bypassed. To fix, simply run the launcher again—it scans and unmounts orphan drives at startup. Alternatively, run subst Z: /D in a Command Prompt.

"No device found" error - how to fix?

Check your cable and ensure it's plugged into a USB 3.0 port. Toggle "USB Debugging" off and back on in your phone's Developer Options. If still not working, choose Option 6 in the launcher dashboard to fully restart the local ADB daemon server.

How do I automate this without prompts?

Run the script with the -NonInteractive switch. This skips folder dialogs, excludes interactive menus, and runs the sync directly using settings stored in settings.json.
